# Baton — 容器隔離

[English](ISOLATION.md) · **繁體中文**

baton 現有的每一道約束,防的都是 agent 的**意外**:資源上限擋住失控的建置,指揮者護欄限縮一條控制連線能提出什麼要求。
但沒有一項能防住一個單純**往昂貴方向做錯**的 agent——而那正是人們把一整隊 agent 丟著不看時,真正害怕的失敗模式。

隔離讓 agent 面板跑在容器裡,這樣一個做錯事的 agent 被關住的是一個工作區,而不是一句承諾。

它**預設關閉,而且以 agent profile 為單位選擇性開啟**。被隔離的面板啟動比較慢、比較難除錯,而且需要一個你自己挑的
image。沒有要求隔離的 profile,行為跟今天一模一樣。

```yaml
# $HOME/.baton/config
panel:
  agents:
    claude:
      command: claude
      isolate: docker # none(預設)| docker
      image: baton/agent:latest # 由你指定,baton 不提供
      mount: workspace # workspace | workspace+home
      network: host # host | bridge | none
      env-allow: [ANTHROPIC_API_KEY] # 其他一律不過去
      user: "" # 空的 = 你自己的 uid:gid
```

## baton 不提供 image

一旦提供了,它就得維護一整張它維護不起的工具鏈矩陣——你的 Go 版本、你的 node、你的測試資料庫用戶端。所以 `image`
是必填的,由你指定。第一版 image 通常就是在你專案本來的建置環境上再加四行,外加 agent CLI。

容器起不來的時候——沒裝 runtime、沒有這個 image、runtime 拒絕某個旗標——**spawn 會直接失敗,並帶著 runtime
自己的訊息**。整條路徑上沒有任何退回未隔離面板的後路,因為退回去產生的正好就是這個設定要防的那件事。

## Agent 保留了什麼

隔離很容易,但要有**用**的隔離 agent 不容易。Agent 之所以有價值,是因為它能跑你的建置、讀你的 repo、連上自己的
API——把它關好之後,這些它一件都做不到。每一個設定鍵就是這其中一項取捨:

| 設定鍵      | 預設        | 關掉之後                            | 保留之後                                  |
| ----------- | ----------- | ----------------------------------- | ----------------------------------------- |
| `mount`     | `workspace` | 工作目錄以外的一切都碰不到          | 就是 agent 被指向的那棵樹,也就是波及範圍  |
| `network`   | `host`      | `none`:什麼都連不到,連模型 API 也是 | `host`:你的 localhost 與整個網路,跟你一樣 |
| `env-allow` | _空_        | 每一個你沒點名的變數                | 只有你列出來的那幾個,逐一指名             |
| `user`      | 你的 uid    | 用 root 寫進你自己的樹裡            | 事後檔案還是屬於你                        |

### `mount`

`workspace` 只掛載面板的工作目錄,其他都不掛。`workspace+home` 額外掛上 `$HOME`,這是靠 `$HOME` 底下某個檔案
做驗證的 agent CLI 要能啟動的最低條件——而它等於把你所有東西交給容器。它是一道逃生門,而這份文件正在把它稱作逃生門。

工作區是掛在**它自己的絕對路徑**上,而不是掛在乾淨漂亮的 `/workspace`。baton 的 git 工具——diff 彈出視窗、git 選單、
worktree 建立——是在**主機端**針對同一個路徑執行的,所以容器如果看到不一樣的路徑,agent 輸出裡的每一個路徑到了
外面都會是錯的。

### `network`

- `host` — 容器共用你的網路命名空間。Agent 連得到模型 API、你的套件庫,以及跑在你 localhost 上的服務。這是預設值,
  因為一個連不上自己 API 的 agent 稱不上 agent。
- `bridge` — runtime 自己的 NAT 網路。對外連得出去,你的 localhost 連不到。在 macOS 上值得選這個,因為那裡的
  host 網路跟 Linux 上不是同一回事。
- `none` — 完全沒有網路。誠實,但只有真的不需要網路的 agent 才用得上。

沒有 egress 白名單。按目的地過濾是遠比在三種立場之間挑一個更大的工程,不在這一版裡。

### `env-allow`

除非 `env-allow` 點名,否則你環境裡的東西一律不會進到容器。每個變數都是以完整的賦值形式傳入,絕不會用會繼承
daemon 手上數值的裸變數名——這才讓這個承諾是可驗證的,而不只是個期望。主機上沒設定的名字傳進去的是**什麼都沒有**,
而不是一個空字串。

### `user`

預設容器以你自己的 uid 與 gid 執行,這樣 agent 就不會在你的樹裡留下 root 所有、事後得 `sudo` 才清得掉的建置產物
——那是隔離本身反而會製造出來的傷害。真的需要 root 的 image(啟動時要裝套件的那種)就寫 `user: root`,或用明確的
`1000:1000` 指定別的身分。

如果 image 裡沒有對應你 uid 的 passwd 項目,它就沒有 `$HOME`,而一個往未設定的 `$HOME` 寫東西的工具會寫到 `/`。
在沒有掛載 `$HOME` 的情況下,baton 會把容器裡的 `$HOME` 指到 `/tmp`。

## 資源上限一樣有效

**[LIMITS.zh-TW.md](LIMITS.zh-TW.md)** 的上限運作方式完全不變——同樣的設定、同樣的兩層、同樣的數值——只是換一個
執行者去守住它:

```txt
未隔離:  面板行程樹外面的 cgroup v2       (只有 Linux)
已隔離:  runtime 自己的 --cpus / --memory / --pids-limit / --ulimit
```

被隔離的面板**刻意不使用** cgroup。那樣關住的會是 runtime 的**用戶端**——一個跟 daemon 講話、只有幾百 KB 的程式
——而容器本身是那個 daemon 的子行程,會完全不受限:一個看起來套用了、實際上什麼都沒守住的上限。

有兩個結果值得知道:

- 隔離之下 `nofile` **真的**生效。它是 cgroup v2 唯一必須回報為無法強制的上限,而 runtime 會把它設在自己啟動的
  行程上。
- 上限第一次在 **macOS** 上真的生效。cgroup v2 只有 Linux 有,所以未隔離的 macOS 面板一直都是不受限的;隔離的不是。
- `C-t R` 改掉的上限**不會**套到執行中的容器上,它從下一次 spawn 開始生效。

## 你放棄了什麼

這些是真正的損失,寫在這裡,而不是留給你之後自己發現:

- **艦隊 socket。** `BATON_SOCK` 不會傳進去,socket 也不會掛載,所以被隔離的 agent 無法驅動艦隊——沒有 `baton ctl`,
  指揮者也無法被隔離。這是對的方向(一個還連得到 socket 的指揮者,等於只被隔離了檔案系統,卻沒被隔離掉它真正能
  動的東西),但它確實是一項損失。面板 id 仍然會傳進去。
- **行程檢視。** `C-t o` 與 `track-cwd: proc` 走的是主機上面板的行程樹,而主機只看得到 runtime 用戶端。Agent 真正的
  行程都在容器裡面。
- **單一面板用量。** 用量頁尾的面板檢視是靠 session id 讀 Claude Code 自己的逐字稿;隔離之下那個檔案寫在容器裡。
  帳號層級的視窗檢視不受影響。
- **啟動時間與 page cache。** 二十個隔離面板就是二十次容器啟動。這一版的隔離是以面板為單位的;讓一個工作項目底下
  的面板共用一個容器,並不在提供的選項裡。

## 它是什麼、不是什麼

它**是**工作區邊界。一個做錯事的 agent——刪錯了樹、改錯了設定、跑錯了腳本——碰得到的只有你掛給它的東西。

它**不是對付惡意 agent 的安全邊界**。Runtime 是以你的 uid、透過你的 docker socket 驅動的,而任何碰得到那個 socket
的東西都碰得到主機。不要把這裡的「容器」讀成「沙箱」。見 **[SECURITY.md](../SECURITY.md)**。

它**不套用在 daemon、指揮者或 shell 面板上**。只有 agent。

它**不是工具鏈管理器**。baton 既不建置也不提供 image,除了 `docker run` 本身會做的事以外,也不會替你去拉 image。
