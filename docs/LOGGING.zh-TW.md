# Baton — 面板記錄

[English](LOGGING.md) · **繁體中文**

一個 agent 跑完一段長工作之後,你真正想要的其實是它**完整的逐字稿**——拿去 grep、貼進 issue、交給另一個 agent、
或是留著備查。Baton 平常只留一份放在記憶體裡的重播緩衝區(`panel.replay-kb`),而那份東西有大小上限,而且會
跟著面板一起消失。

記錄功能改成把面板的輸出寫進檔案。兩個按鍵:

| 按鍵    | 作用                                    |
| ------- | --------------------------------------- |
| `C-t l` | 開始／停止記錄選取的面板                |
| `C-t L` | 用臨時面板開啟它的記錄檔,並持續跟著它跑 |

記錄**預設是關的**,而且在你指定一個目錄之前都會保持關閉。一個會把你的終端機寫進磁碟的功能,應該是你主動打開的。

```yaml
# $HOME/.baton/config
panel:
  log-dir: ~/.baton/logs # 記錄檔放哪裡;留空(預設)就是完全不記錄
  log-max-mb: 64 # 到這個大小就輪替,只保留前一代

  agents:
    claude:
      command: claude
      log: true # 這個 profile 從 spawn 的那一刻就開始記錄
      log-dir: ~/work/transcripts # 選用:這個 profile 自己的目錄
```

## 檔案落在哪裡

落在**隊伍實際執行的那台機器**上。PTY 是 daemon 持有的,所以寫檔的也是 daemon——在 `--remote` 之下,那並不是你
操作介面所在的機器。這也正是 `C-t L` 開的是一個**面板**而不是一個檢視器的原因:操作介面自己從不碰那個檔案,所以
本機跟遠端讀回記錄的方式完全一樣。

檔名是 `<log-dir>/<yyyy-mm-dd>-<面板標題>-<id>.log`,經過 slug 化。日期放最前面,所以整個目錄天然按時間排序;
id 放最後,所以同一天同名的兩個面板永遠不會撞在一起。

## 寫進去的是什麼

**純文字,escape sequence 已經拿掉**——跟 `fleet.search`(`/`)回傳的形狀一樣。這個檔案是拿來 grep、貼上、
以及讓另一個 agent 重讀的,這三件事沒有一件會想看到滿螢幕的 `\x1b[2K`。

代價很誠實,而且值得在你去翻檔案之前先知道:**會重畫的 agent 會把草稿一起留下來**。進度條、轉圈圈、清畫面——
每一個中間狀態都是真的輸出過的一行,而一個把某行原地改寫的 carriage return 在檔案裡會變成新的一行,而不是消失。
所以一段有轉圈圈的執行,會產生一個把每一格動畫都留著的檔案。之後也許會有 raw bytes 模式;這一版不是。

顏色、游標移動、視窗標題序列都會被丟掉。Tab 跟換行會留著。

## 它是從哪裡開始的

打開記錄時,會**先把面板現有的重播緩衝區倒進檔案**,然後才開始接續串流。你會伸手去按這個鍵,正是**因為**剛剛
發生了什麼有意思的事;一份從按鍵那一刻才開始的記錄,剛好會漏掉讓你按下去的那件事。

那段前綴唯一沒辦法誠實聲稱的,是裡面每一行**發生的時間**——重播環是位元組,不是事件——所以它直說,而不是假裝
自己知道:

```txt
=== baton log · claude · ~/work/api ===
=== logging started · 2026-08-18T15:04:05+08:00 ===
--- replay buffer: output from before logging started; its timestamps are not known ---
  ✻ Thinking…
  ● Read src/server.go
=== live output follows · 2026-08-18T15:04:05+08:00 ===
```

## 工作階段與重跑

重跑(`r`)會**在新的 session 標記底下接續寫**,而不是把檔案截斷:上一輪執行通常正是你在讀這個檔案的原因。

```txt
=== process exited (code 1) · 2026-08-18T15:31:02+08:00 ===
=== session restarted · 2026-08-18T15:31:40+08:00 ===
```

面板的行程結束時、記錄被關掉時、面板被關閉或清除時、以及 daemon 關機時,檔案都會被 flush 並關閉——而且各自帶一個
說明是哪一種情況的標記。一份記錄永遠不會就這樣停在半行,什麼都不交代。

之後再打開記錄一樣是接續寫,所以一個面板的檔案裡會有你要求記錄過的每一輪執行。

重跑會沿用當下的記錄狀態:原本正在記錄的面板回來時仍在記錄,原本沒在記錄的仍然不記錄——包含那些 profile 設定為
自動記錄、但被你手動關掉的面板。

## 讓某個 profile 自動記錄

`panel.agents.<name>.log: true` 會讓那個 profile 從 spawn 的那一刻就開始記錄。這是 per-profile 而不是全隊的開關,
因為真正會發生的需求是「每個 agent 都記,但我的 shell 一個都不要」——而一個全域開關會安靜地把你在 shell 裡打的
每一個字都寫到磁碟上。

如果這種面板 spawn 的時候目的地寫不進去,**面板還是會照常起來**,只是不記錄,而且原因會被回報。Agent 才是重點,
記錄是附加品;一個打錯的路徑應該讓你損失逐字稿,而不是損失那一次執行。

## 磁碟

`log-max-mb`(預設 64)會把檔案輪替成 `<file>.log.1` 並開一份新的,只保留**最近兩代**,不會更多。一個失控的
建置可以在幾分鐘內產出好幾 GB,而 baton 在 **[LIMITS.zh-TW.md](LIMITS.zh-TW.md)** 裡本來就主張:不該有任何東西
能把整台機器一起帶走——記錄檔也不例外。

沒有保留期限的清掃機制。舊的記錄要留還是要刪,是你的事。

## 把它讀回來

`C-t L` 會用一個**臨時面板**開啟記錄檔——跟 git 選單用的是同一套 ephemeral 機制。它會在結束時、以及回到儀表板的
路上被回收,永遠不會變成隊伍裡的一張卡片。

它會**跟著檔案跑**(`less +F`,在沒有 `less` 的機器上退回 `tail -f`),因為它所屬的那個面板通常還在執行。在
`less` 裡,`C-c` 會停止跟隨,讓你往回翻之前的內容;`q` 關掉面板。

## 讓你知道它是開著的

正在記錄的面板會**在儀表板卡片上帶一個標記**——狀態 LED 前面的 `◉`——而且在那個面板被聚焦時,頁尾會寫出檔名:

```txt
◉ LOG …/logs/2026-08-18-claude-3.log
```

一個會安靜地把你的終端機寫進磁碟的功能,在它做這件事的時候必須看得見。這個狀態是隊伍的狀態,不是操作介面的狀態:
它住在 daemon 上,所以能撐過 detach 與重新連接,而且連到同一個隊伍的每個操作介面看到的都一樣。它刻意**不會**跨
daemon 重啟保存——一個你忘記關掉的記錄開關安靜地繼續寫,才是比較糟的失敗。

## 它是什麼,不是什麼

它是一份**逐字稿**:面板印出來的東西,純文字,放在 daemon 的磁碟上。

它**不是稽核邊界**。檔案是由一個以你的身分執行的 daemon,寫進一個你擁有的目錄;任何能碰到那個 uid 的東西都能改它
或刪它——包括正在被記錄的那個面板裡的 agent。見 **[SECURITY.md](../SECURITY.md)**。

它**不是錄影格式**。沒有 asciinema／raw 模式,沒有逐行時間戳,沒有 JSON。它就是文字。

conductor **碰不到它**。`panel.log` 與 `panel.logview` 對 conductor 角色的連線一律拒絕,理由跟收件匣那組動詞一樣:
要求 daemon 在 daemon 的主機上、以你的身分寫檔案,是操作者的動作。見 **[CONTROL.zh-TW.md](CONTROL.zh-TW.md)**。

## 相關按鍵

| 按鍵    | 作用                                                  |
| ------- | ----------------------------------------------------- |
| `C-t l` | 開始／停止記錄選取的面板                              |
| `C-t L` | 用臨時面板開啟該記錄檔,並持續跟著它跑                 |
| `C-t R` | 重載設定;新的 `log-dir` 會套用到之後才開的記錄檔      |
| `/`     | grep 每個面板的即時重播緩衝區——記錄檔在記憶體裡的兄弟 |
