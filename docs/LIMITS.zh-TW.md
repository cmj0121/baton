# Baton — 資源上限

[English](LIMITS.md) · **繁體中文**

放著不管的 agent 可以把整台機器吃光:一個失控的測試套件、一個 fork 到風扇狂轉的建置、一個長到把其他東西全部
擠進 swap 的行程。Baton 可以限制每個面板能用多少資源——CPU、記憶體、行程數——而且管的是它**整棵行程樹**,
不只是你啟動的那個 agent 執行檔。

上限**預設是關的**。沒有設定過的 baton 不會限制任何東西,也完全不會碰 cgroup。

```yaml
# $HOME/.baton/config
panel:
  # 全隊底線:除非某個 profile 另有規定,每個面板都跑在這組上限下。
  limits:
    cpus: "2" # CPU 核數;可以有小數("1.5")
    memory: 4Gi # 硬上限——碰到就會殺掉整棵樹
    memory-high: 3Gi # 先節流、後才殺的水位線
    pids: 512 # 整棵樹最多幾個行程/執行緒——防 fork bomb 的那道
    nofile: 4096 # 每個行程的開檔數(見「哪些沒有被強制」)

  agents:
    claude:
      command: claude
      limits: { memory: 8Gi } # 繼承上面的 cpus/pids,只把 memory 調高

    heavy-build:
      command: claude
      limits: { cpus: "8", memory: 16Gi, pids: unlimited }
```

## 一個上限的三種狀態

每個上限都寫成字串,因為它必須能表達三件不同的事:

| 寫法          | 意義                     |
| ------------- | ------------------------ |
| _欄位不存在_  | **繼承**上一層設定的值   |
| `"2"` / `4Gi` | **限制**在這個值         |
| `unlimited`   | **解除**上一層設下的限制 |

這就是為什麼上限不是數字。`0` 會同時得表示「繼承」和「不限」,而且 profile 將永遠無法解除全隊區塊設下的上限
——它只能把上限收得更緊。

**量值寫法。** 大小兩套單位都吃:二進位 `4Gi` / `512Mi` / `1.5Gi`、十進位 `2G` / `500M`、純位元組數,結尾多一個
`B` 也沒問題(`4GiB`)。`cpus` 是核心數而不是百分比——`"2"` 表示每一秒實際時間可以用掉兩個核心的 CPU 時間。
Baton 讀不懂的量值會在載入設定時退回「繼承」,所以一個錯字只會讓你少掉那一個上限,而不會把常駐程式弄壞。

## 兩層疊加

一個面板實際生效的上限,是全隊的 `panel.limits` 再蓋上它所屬 **agent profile** 的設定,逐欄位覆寫:

```txt
panel.limits:        cpus 2 · memory 4Gi · pids 512
agents.claude:                 memory 8Gi
                     ─────────────────────────────────
實際生效:            cpus 2 · memory 8Gi · pids 512
```

Profile 只需要重述它要改的部分。Shell 面板(包含 global shell)以及任何沒帶 profile 產生的 agent,都只吃全隊
那一層。

**政策由伺服器解析,絕不由客戶端提供。** `panel.create` 只送出 profile 的**名字**,由常駐程式在自己的設定裡查
表。這件事很重要,因為 baton 的客戶端之一**本身就是 agent**——指揮官透過同一個 socket 驅動整支隊伍——所以
「客戶端能送的政策」就等於「agent 能放寬的政策」。受限連線的 profile 名字會在圍籬處被清掉,也就是說由 agent
發動的產生(`baton ctl`、MCP 工具、指揮官)一律落在全隊那層上限。

## 在座艙裡編輯

`C-t P` 打開**面板設定**,全隊上限就在 RESOURCE LIMITS 區塊裡——`↑↓` 移動、`e` 編輯、`enter` 存檔。Baton 讀
不懂的值會被擋下來,而且 overlay 會停在你剛才輸入的內容上,讓你直接改錯字而不用整行重打。

```txt
╭───────────────────────────────────────────────────────────────────────╮
│   P A N E L   C O N F I G                                             │
│                                                                       │
│     default shell   /bin/zsh                                          │
│     replay buffer   512 KiB                                           │
│                                                                       │
│   R E S O U R C E   L I M I T S                                       │
│                                                                       │
│     cpus            2                                                 │
│   ▸ memory          4Gi                                               │
│     memory-high     no cap                                            │
│     pids            512                                               │
│     nofile          no cap                                            │
│                                                                       │
│   limits cap a panel's whole process tree · enforced by cgroup        │
╰───────────────────────────────────────────────────────────────────────╯
```

最後那一行是要先看的:它告訴你這個畫面上的上限**在這台主機上到底有沒有效**(見
[在哪裡被強制](#在哪裡被強制))。Per-agent 的上限請直接編輯 `$HOME/.baton/config`——座艙只編全隊那一層。

## 重載

`C-t R`(或對常駐程式送 `SIGHUP`)會把新的上限套用到**正在跑的隊伍**上,什麼都不用重啟:

- **cpus、pids、memory-high** —— 對每個活著的面板立即生效。
- **memory** —— **調高**上限會立刻套用。**調低**則會等到該面板下次重跑(`r`):把硬上限寫成比整棵樹當下用量
  還小的值,會讓核心立刻對著它回收並把工作到一半的 agent 殺掉,那比晚一點才生效更糟。無論如何 `memory-high`
  都會即刻以新值開始節流,所以調低上限仍然會馬上把整棵樹壓慢。

面板記錄的是它產生時所用 profile 的**名字**,而不是那個名字當時解析出的上限。所以一次重載就會把每個活著的面板
重新指向新政策;而你從設定裡刪掉的 profile 會退回全隊上限,不會留下過期的覆寫。這件事也撐得過重啟:還原的面板
會沿用當初那個 profile 去解析。

## 在哪裡被強制

| 主機                          | 後端     | 你會得到什麼                              |
| ----------------------------- | -------- | ----------------------------------------- |
| 有委派 cgroup v2 子樹的 Linux | `cgroup` | cpus、memory、memory-high、pids——管整棵樹 |
| 沒有委派的 Linux              | `none`   | 什麼都沒有;會回報原因                     |
| macOS 及其他                  | `none`   | 什麼都沒有;cgroup v2 只有 Linux 有        |

強制手段是 **cgroup v2**,而之所以是 cgroup 而不是 `ulimit`,只有一個理由:被限制的單位必須是整棵行程樹。
Agent 會去 fork node、git、測試執行器;而 rlimit 是 per-process 而且會被繼承,所以 4Gi 的 rlimit 意思是**每個**
子孫都可以各拿 4Gi。cgroup 則是把它們合起來一起算。

每個面板是透過 `clone3(CLONE_INTO_CGROUP)` 被放進自己的 cgroup 的——子行程的第一道指令就已經在上限之內執行,
所以不存在「趁隙 fork 出一個逃掉的子孫」的空窗。

**無法強制的主機會大聲說出來。** 啟動時會寫進常駐程式的 log,面板設定的頁尾也會顯示
`NOT enforced here · <原因>`。看起來有生效、實際上沒有的上限,比你從來沒設過還糟,所以 baton 不會讓這件事悄悄
發生。在 macOS 上,誠實的選項是 Linux VM,或每個 agent 一個容器。

**哪些沒有被強制。** `nofile` 是開檔數上限,屬於 per-process 的 `RLIMIT_NOFILE` 範疇而不是 cgroup 的旋鈕——
設定裡收得下,但會被回報為無法強制,等待 rlimit 後端。若主機只委派了部分 controller,**能**套用的上限仍然會
套用,其餘則在每次產生時寫進 log。

## 它是什麼、不是什麼

它是**資源**邊界:不管 agent 跑什麼,它都拿不到超過你允許的 CPU、記憶體或行程數。

它**不是安全邊界**。Agent 仍然以你的身分、在你的檔案系統、用你的網路執行。它能讀你的檔案、能連網,跟以前一模
一樣——見 **[CONTROL.md](CONTROL.zh-TW.md#護欄)** 的護欄說明。檔案系統與網路的隔離需要另一種後端,而 baton 有一個:
**[ISOLATION.zh-TW.md](ISOLATION.zh-TW.md)** 能讓某個 agent profile 的面板跑在容器裡,選擇性開啟。它關得住做錯事的
agent,但仍然不是對付惡意 agent 的邊界;而下面這些上限在容器裡外一樣有效——只是由 runtime 自己的旗標而非 cgroup v2
去執行,這也是為什麼它們在 macOS 上只有面板被隔離時才守得住。

它也**不是花費邊界**,而這件事值得直說,因為「對 agent 能耗用的量設下真正的天花板」聽起來很像連帳單也管了。它沒有。
**baton 裡沒有任何東西限制一個 agent 用掉多少 token**——這些上限沒有,agent profile 沒有,任務佇列也沒有。
`cpus`、`memory` 與 `pids` 約束的是機器的資源;一個被限制在半顆核心的 agent,可以在一個下午燒掉一個月的預算,
而完全不碰到其中任何一項。**[USAGE.zh-TW.md](USAGE.zh-TW.md)** 是**事後**測量花費的——它讀的是已經計費的數字,
把它顯示在頁尾,並附上到下次視窗重置的倒數——而 baton 裡沒有任何機制能在事前把它框住。如果你需要一個硬性的花費
上限,那必須來自你的供應商自己的控制項。
