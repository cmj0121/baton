AI 코딩 agent를 한 번에 여러 개 돌리고 있나요? 상황은 금방 엉망이 됩니다 — 이리저리 옮겨 다녀야 하는 창들,
탭마다 흩어진 session, 그리고 누가 일하는 중이고 누가 막혔으며 누가 당신을 기다리는지 한눈에 볼 곳이 없죠.

Baton과 AI agent의 관계는 tmux와 shell의 관계와 같습니다. Baton은 **키보드만으로 조종하는 하나의 조종석**을
줍니다. 모든 agent를 담은 실시간 대시보드에서, 각 agent는 자신이 속한 작업별로 묶이고, 어느 것이든 키 하나
거리에 있습니다.

지휘봉은 당신 손에 있습니다. agent들이 연주하고, 당신이 지휘합니다. 🎼

![Baton 조종석 데모 — 먼저 키 목록, 패널 띄우기, conductor 열기, 둘을 작업 항목으로 묶기, 그리고 분할 화면과 확대 화면에서 같은 ? 키](assets/baton-demo.png)

_키 하나로 한 바퀴를 돕니다. `?`는 지금 서 있는 뷰의 키를 보여 주고, 패널을 띄우고, `n C`로 conductor를 부르고,
`g g` 다음 `g c`로 둘을 작업 항목으로 묶습니다 — 그리고 분할 화면의 `?`와 확대 화면의 `C-t ?`는 서로 다른 세 개의 표입니다._

_영상은 [`baton-demo.tape`](assets/baton-demo.tape)로 만들었습니다. 영상 속 conductor의 agent CLI는 대역
([`demo-agent.sh`](assets/demo-agent.sh))이라 어느 머신에서도 같은 영상이 녹화되며, 그것이 socket으로 몰아가는
함대는 진짜입니다._

## 시작하기

Baton은 단일 정적 실행 파일입니다. macOS에서는 [Homebrew](https://brew.sh)로 가볍게 설치하세요.

```sh
brew install cmj0121/tap/baton
```

Linux에서는 한 줄이면 됩니다.

```sh
curl -fsSL https://raw.githubusercontent.com/cmj0121/baton/main/scripts/install.sh | sh
```

…또는 플랫폼을 가리지 않고 [Go](https://go.dev) 1.26+ 로 받을 수도 있습니다.

```sh
go install github.com/cmj0121/baton/cmd/baton@latest
```

…또는 clone 받은 소스에서 `make install`로 빌드하세요. 그다음 그냥 실행하면 됩니다.

```sh
baton
```

Baton은 백그라운드 서버를 띄우고 당신을 **대시보드** — 당신의 본진 — 에 내려놓습니다. 첫 1분은 이렇게
보내세요.

1. **`A`** 를 눌러 agent를 띄웁니다(작업 디렉터리를 고르게 됩니다).
2. **`enter`** 를 눌러 확대해 일하는 모습을 지켜보고, **`C-t d`** 로 대시보드에 돌아옵니다.
3. **`q`** 를 눌러 분리(detach)하고 자리를 떠나세요 — 모든 것은 계속 돌아갑니다. 언제든 `baton`으로 돌아오면
   됩니다.

길을 잃었나요? **`?`** 는 지금 있는 화면의 키를 언제나 보여줍니다.

## 그냥 tmux를 쓰면 안 되나요?

tmux는 pane 안에 무엇이 있는지 모르기 때문입니다. tmux는 창을 줄 뿐, 어느 것이 무엇인지는 당신이 기억해야 하고,
어떤 agent가 계속 당신을 기다리고 있었다는 사실은 하나씩 넘겨 보다가 알게 됩니다. Baton은 pane 안에 agent가
있다고 전제하며, 나머지는 거기서 따라 나옵니다:

| 하고 있는 일          | tmux로 직접                      | Baton                                                                           |
| --------------------- | -------------------------------- | ------------------------------------------------------------------------------- |
| 누가 기다리는지 찾기  | 창을 하나씩 넘겨 가며 읽기       | 패널마다 살아 있는 상태, 그리고 사람을 기다려 멈춘 것들이 모이는 `C-t a` 받은함 |
| 관련된 일을 묶어 두기 | 창 이름을 붙이고 규칙을 기억하기 | 작업 항목 — 이름 붙은 패널 묶음, 키 두 번이면 된다                              |
| 일을 넘기기           | 매 pane마다 직접 타이핑          | 하나 또는 그룹 전체에 task를 보내거나, conductor agent가 함대를 몰게 하기       |
| 폭주하는 빌드 막기    | 없음                             | CPU·메모리·프로세스 수 상한을 패널의 프로세스 트리 전체에                       |
| 비용이 얼마인지 알기  | 없음                             | 청구 구간의 토큰과 비용, 그리고 할당량 막대를 패널 단위로                       |

Baton은 tmux의 대체재가 아니고 당신의 shell을 원하지도 않습니다 — tmux 안에서 살고 있다면 그 안에서 실행하세요.

## 개념

- **shell이 아니라 agent.** 작업의 단위는 돌보아야 할 창이 아니라, 실행 중인 agent입니다.
- **창이 아니라 대시보드.** 탭 더미가 아니라, 전부를 한 번에 보는 실시간 개요입니다.
- **헤드리스 코어, 교체 가능한 프런트엔드.** 두뇌는 백그라운드 데몬이고, 그것을 그려내는 얼굴은 갈아 끼울 수
  있습니다.

| 개념             | 무엇인가                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------- |
| **Panel**        | 하나의 라이브 터미널 — _agent_ 패널(agent CLI) 또는 _shell_ 패널.                                       |
| **Work item**    | 하나의 작업에 속하는, 이름이 붙은 패널 묶음.                                                            |
| **Task**         | agent에게 넘기는 지시서 — 생명주기 전반이 추적되며, 기다려야 한다면 큐에 넣고 스케줄링됩니다.           |
| **Conductor**    | 당신을 대신해 함대를 몰아주는 agent — socket 너머로 다른 패널을 띄우고, 묶고, 프롬프트를 보냅니다.      |
| **Global shell** | 서버가 `$HOME`에 하나만 쥐고 있는 순수 호스트 shell, 언제나 키 하나 거리 — 함대의 조종자가 아니라 본진. |

## 화면

Baton은 세 가지 화면으로 조종하며, 키 하나로 그 사이를 오갑니다.

- **대시보드(Dashboard)** — 관제탑. 작은 함대는 패널마다, 작업 항목마다 한 장씩인 **카드** 격자로 그려지고,
  최상위 항목이 여섯 개가 되는 순간 모든 패널을 보여주는 실시간 **트리**로 바뀝니다. 작업 항목이 한 행이고, 그 하위
  그룹이 아래로 들여쓰기되며, 패널은 다시 그 아래에 놓입니다. `space` 는 어느 깊이에서든 그 행 아래 중첩된 것을
  보이거나 감추고, `→` 로 작업 항목을 열고 안으로 들어가며, `←` 로 닫고 밖으로 나옵니다 — 최상위에서 한 번 더
  누르면 카드로 돌아갑니다. 행에는 터미널 폭에 따라 상태, 작업 디렉터리, 출력 스파크라인, 배정된 작업이 차례로
  더해지고, `v p` 로 옆에 상세 창을 띄울 수 있습니다. 여기서 이동하고, 패널을 띄우고 닫고, 작업 항목으로 묶습니다.
- **그룹(Group)** — 한 작업 항목의 실시간 분할 화면. 소속 패널들이 나란히 타일로 깔려 모두 동시에 스트리밍
  됩니다. 앞의 몇 개는 라이브 타일로 흐르고, 나머지는 하나의 **요약 타일**로 접혀 확대해 볼 수 있습니다. 몇
  개를 고정(pin)해 항상 켜 두거나, **`i`** 로 포커스된 패널을 그 자리에서 조작하거나, **`enter`** 로 그 안에
  들어가세요.
- **확대(Zoom)** — 패널 하나가 당신의 유일한 터미널이 됩니다. 키 입력은 곧바로 프로그램으로 가고, 리더 키
  **`C-t`** 가 동작을 취하거나 한 단계 물러나는 방법입니다.

## 키

키는 **모달(modal)** 입니다. 대시보드와 그룹에서는 각 동작이 키 하나이고, 확대나 상호작용 중에는 키 입력이
프로그램을 조작하므로 Baton의 동작은 리더 키 **`C-t`** 다음에 그 키를 누르는 형태가 됩니다. 현재 화면의
완전하고 재바인딩 가능한 목록은 **`?`** 로 보고, 키 맵 편집은 **`C-t k`** 로 하세요.
네 개의 키는 랜딩 키입니다. 혼자서는 아무 일도 하지 않고 한 묶음을 엽니다 — `n` 은 띄우기, `v` 는 표시, `g` 는
그룹, `x` 는 스스로를 확인하는 두 번 누르기 — 상태 바가 다음에 받을 수 있는 키를 알려줍니다.

| 어디서      | 키                    | 동작                                                       |
| ----------- | --------------------- | ---------------------------------------------------------- |
| After `C-t` | `d` / `b`             | 대시보드로 이동 / 한 단계 뒤로                             |
|             | `a`                   | attention 수신함 — 사람이 필요한 것을 처리                 |
|             | `[`                   | 스크롤 모드로 진입                                         |
|             | `l` / `L`             | 패널을 파일로 기록 / 그 기록을 다시 열기                   |
|             | `R` / `S`             | 설정 다시 읽기 / 서버 강제 재시작                          |
|             | `q`                   | 분리(서버는 계속 실행)                                     |
| Dashboard   | `jk` / `↑↓`           | 커서 이동                                                  |
|             | `hl` / `←→`           | 카드 한 칸 이동 · 트리에서는 작업 항목 접기 / 펼치기       |
|             | `space`               | 행 아래 중첩된 것을 보이기 / 감추기                        |
|             | `v p` / `v g`         | 상세 창 / 그룹 기준 순환: 작업 항목·디렉터리·프로파일·상태 |
|             | `v l`                 | 대시보드 레이아웃: 카드 또는 트리                          |
|             | `m`                   | 행 집기 — 화살표로 옮기고 `enter` 로 놓기                  |
|             | `enter`               | 선택 항목 열기 / 확대                                      |
|             | `p` / `A` / `n c`     | 새 shell / agent / 명령 선택 패널                          |
|             | `n .`                 | 포커스된 패널의 디렉터리에 새 shell 패널                   |
|             | `n C`                 | conductor 열기(함대를 몰아주는 agent)                      |
|             | `n h`                 | global shell 열기(`$HOME`의 호스트 shell)                  |
|             | `w` / `x x`           | 선택 항목 닫기 / 종료된 것 정리                            |
|             | `r`                   | 포커스 아래의 종료된 패널 다시 실행                        |
|             | `g g` / `g c` / `g u` | 표시 / 표시한 패널 묶기 / 묶음 해제                        |
|             | `s` / `f` / `D`       | 선택 항목에 시그널 / 찾기 / diff                           |
|             | `/`                   | 모든 패널의 출력 검색(함대 전체 grep)                      |
|             | `T` / `Q`             | 작업 배정 / 작업 큐 관리                                   |
|             | `v u`                 | 사용량 푸터 전환: 끄기 / 청구 창 / 포커스 패널 / 한도      |
|             | `v U`                 | 계정 사용량 — 한도 막대와 소비 중인 패널                   |
|             | `v k`                 | 푸터의 키 입력 표시 토글                                   |
| Group       | `tab`                 | 다음 패널로 포커스                                         |
|             | `+` / `-`             | 라이브 타일 늘리기 / 줄이기                                |
|             | `L`                   | 타일 레이아웃 순환                                         |
|             | `p` / `i`             | 포커스된 패널 고정 / 조작                                  |
|             | `enter`               | 포커스된 패널 확대                                         |
| Zoom        | 타이핑                | 프로그램을 직접 조작                                       |
|             | `C-t f` / `C-t G`     | 스크롤백 검색 / git 메뉴(agent)                            |

완전한 키 참조는 **[docs/KEYS.md](KEYS.md)** 를, 각 화면 뒤의 설계는 **[docs/SPEC.md](SPEC.md)** 를 보세요.

## 기능

터미널 멀티플렉서가 하지 못하는 다섯 가지:

- **폴링하지 않는 주의** — 함대는 대개 멀쩡합니다. 화면을 보고 있는 이유는 멀쩡하지 않은 몇 개 때문이죠. 하나의
  조용한 시계가 모든 패널을 줄 세웁니다 — `running`, 10초의 `idle`, 한 턴을 마친 agent의 `done`, 너무 오래 끈
  `stuck` — 그리고 agent는 스스로 손을 들어 이 사다리 전체를 앞지를 수 있습니다. `C-t a`는 어느 화면에서든 받은함을
  열고, 대기열은 거기서 정리됩니다. `settings.notify`는 아무도 보고 있지 않을 때 OSC 9 데스크톱 알림을 보내되
  묶어서 보내며, `done`으로는 결코 울리지 않습니다. **[docs/ATTENTION.md](ATTENTION.md)** 참고.
- **conductor** — `n C`는 함대를 대신 몰아 주는 agent를 엽니다. socket을 통해 — `baton ctl`이나 `baton mcp`
  도구로 — 패널을 띄우고, 묶고, 시그널을 보내고, 다른 패널에 프롬프트를 넘깁니다. 자기 호스트를 망가뜨리지 못하도록
  울타리가 쳐져 있습니다. 목표는 `$HOME/.baton/CONDUCTOR.md`에. **[docs/CONTROL.md](CONTROL.md)** 참고.
- **task와 대기열** — `T`는 브리프를 한 agent에게, 또는 작업 항목 전체에 뿌립니다. 카드에 기록되고 agent가 준비되면
  전달됩니다. `Q`는 지속되는 백로그를 관리하고, 서버가 가진 스케줄러가 이를 비어 있는 agent에게 흘려보냅니다.
  Lua `task.pre` 훅은 브리프를 고치거나 거부할 수 있고, `task.change`는 그것을 지켜봅니다.
- **프로세스 트리 전체에 걸리는 상한** — 패널이 쓸 수 있는 CPU·메모리·프로세스 수를 제한하고, 그 프로세스 트리
  전체를 그 안에 붙잡아 둡니다. 폭주하는 빌드가 머신을 통째로 끌고 가지 못하도록. 함대 전체의 바닥값과 agent별
  덮어쓰기, `C-t R`로 돌고 있는 함대에 적용, 리눅스에서는 cgroup v2로 강제 — 강제할 수 없는 호스트에서는 패널이
  그렇게 말합니다. **[docs/LIMITS.md](LIMITS.md)** 참고.
- **패널까지 추적되는 사용량** — `v u`는 푸터 표시를 돌려 가며 보여 줍니다: 청구 구간의 토큰과 비용, 그리고 카운트다운
  (`⊙ 1.2M tok · ≈$12.34 API · ⏳ 2:14:31`), 포커스된 패널의 몫, 또는 계정의 rate-limit 막대
  (`⊙ 5h ▓▓▓▓▓░░░ 2:14:31 · 7d ▓▓▓░░░░░ 3d4h`). `v U`는 전부를 엽니다 — 모든 할당량 구간, 추가 사용 크레딧,
  그리고 그것을 먹고 있는 패널. **[docs/USAGE.md](USAGE.md)** 참고.

대부분의 멀티플렉서에도 없는 네 가지 더:

- **컨테이너 격리** — agent 프로필 단위의 선택 기능입니다. `isolate: docker`면 그 프로필의 패널은 워크트리를 마운트한
  컨테이너 안에서 돕니다. 이미지는 직접 지정하고(Baton은 제공하지 않습니다), `mount`·`network`·`env-allow`·`user`가
  그 밖에 무엇이 넘어갈지 정하며, 환경 변수는 지목하지 않는 한 넘어가지 않습니다. 기본은 꺼져 있고, 적대적인 agent에
  대한 경계는 아닙니다. **[docs/ISOLATION.md](ISOLATION.md)** 참고.
- **함대 전체 grep** — `/`는 모든 패널의 출력을 한 번에 검색하고 결과를 패널별로 묶어 보여 줍니다. `enter`로 고른
  것을 확대하면 일치한 지점에 내려앉습니다. `C-t f`는 한 패널의 스크롤백을 정규식으로 찾고, 스크롤 모드(`C-t [`)는
  OSC 52로 선택해 복사하므로 SSH 너머에서도 보조 바이너리 없이 동작합니다.
- **agent 백엔드** — Baton은 agent CLI 명부(`claude`, `codex`, `gemini`, `aider`, `opencode`, `grok`)를 알고 있고,
  함대가 도는 머신에 실제로 무엇이 있는지 탐지합니다. `A`는 고른 것을 띄우고, `C-t P`는 함대 기본값을 정하면서 없는
  것들의 설치처를 함께 보여 주며, `C-t R`은 설치 뒤 다시 탐지합니다. 직접 만든 것은 `panel.agents` 아래에.
- **원격 접속** — `baton --remote`는 같은 조종석을 다른 머신의 함대에 붙입니다. 이미 쓰고 있는 ssh만 쓰며 수신
  포트도, TLS도, Baton 고유의 키 교환도 없습니다. 기본은 꺼짐. `C-t @`가 켜고, 디스크에 쓰이지 않는 passkey를 발급하고,
  살아 있는 연결을 모두 보여 주어 끊거나 바꾸거나 닫게 합니다. **[docs/REMOTE.md](REMOTE.md)** 참고.

그리고 멀티플렉서라면 당연히 있어야 할 조종석, 모두 키 하나 거리에:

| Diff          | `D`             | agent 패널의 작업 트리 diff — staged와 unstaged를 한 번에, 미추적 포함             |
| Git           | `C-t G`         | diff·log·status·stage·commit·push·branch·worktree — **[docs/GIT.md](GIT.md)**      |
| 시그널        | `s`             | 선택·포커스된 타일·그룹 전체에 임의의 시그널                                       |

| global shell  | `n h`           | 서버가 `$HOME`에 쥐고 있는 순수 호스트 shell 하나, 언제나 키 하나 거리             |

## 아키텍처

헤드리스 **baton server**(백그라운드 데몬)가 모든 상태와 모든 터미널을 소유합니다. 교체 가능한 프런트엔드는
단 하나의 Unix 도메인 socket으로 붙습니다 — 명령은 위로, 이벤트는 아래로 — 그래서 분리했다가 다시 붙어도 아무
것도 잃지 않습니다.

전체 다이어그램과 상호작용 모델은 **[docs/SPEC.md](SPEC.md)** 를 보세요.

## 플러그인

Lua 파일 하나(`$HOME/.baton/plug-in.lua`)면 Baton을 당신의 워크플로에 맞게 다시 빚을 수 있습니다: 생명주기
이벤트에 반응하고(agent가 당신을 필요로 할 때 알려주기, 하나가 끝나면 다음 단계로 이어 붙이기), 함대를 몰고,
자신만의 명령을 추가하고, 설정을 지정하는 것까지 — 전부 하나의 `baton` 객체를 통해서.
**[docs/PLUGIN.md](PLUGIN.md)** 를 보세요.
